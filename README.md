# 作業日誌 困りごと分析ダッシュボード（日→週→月のルーティン版）

同じ作業日誌を、**毎日3分 書く → 毎週10分 確かめる → 毎月30分 決める** という時系列のリズムで回すダッシュボード。
時間の粒度が上がるほど、機械の仕事が減り、人の判断が増えるように並べている。
テキスト分析 第1回〜第3回の積み上げ（学ぶ）と、発展の分析（深掘り）はそのまま残している。

## 起動

```bash
pip install -r requirements.txt
streamlit run app.py
pytest -q          # 計算部品の検証（期待値は人が先に決めたもの）
```

ページは URL で直接開ける：`http://localhost:8501/nisshi`・`/shukei`・`/tsuki`

## 毎日のルーティン（主軸）

| いつ | /コマンド | 3段構え | 機械がすること | 人がすること | 残るもの |
|---|---|---|---|---|---|
| 毎日（3分） | `/nisshi` | ① 現象を計算する | 匿名化・語の一致・否定の可能性 → タグ案 | 例「柿の木を観察。落葉の片づけが遅れている」。写真を入れ、タグ表に **OK／直し** | 日誌1行・タグの確認 |
| 毎週（10分） | `/shukei` | ② 可視化して確かめる | 今週の候補を集め、判定モデル（⑥）の確率順に並べる | 候補の日誌が**本当に困りごとか**を判定 | 判定（教師データ） |
| 毎月（30分） | `/tsuki` | ③ 自分の条件で判断する | 月の割合（Beta推定・90%区間）・前月より高い確率・優先度の目安 | **準備度**を答え、**手を打つ順番**・打つ手・担当・期限を決める | 決定（翌月のふりかえりに使う） |

ホーム「今日のルーティン」には、3つの状態（今日書いたか・今週の未判定・今月決めたか）と、
**記入リズム（曜日×週のヒートマップ）＋週ごとの判定状態**の時系列を並べる。

### つながり方

- **日 → 週**：日次で人が確認したタグ（OK／直し）が週次の候補になる。確認していない日誌はルール（一致かつ否定なし）で候補にする。
- **週 → 月**：月次の数字は、既定で「人が困りごとと判定した日誌」で数える。未判定が残っていれば警告し、`/shukei` へ戻す。
- **月 → 翌月**：前月に決めた手と、今月の割合を並べてふりかえる（**前後関係であって、効いた証明ではない**）。

### 優先度の目安（/tsuki）

```
優先度 = 起きやすさ × (1 − 準備度/3) × (1 + w × max(0, P(前月より高い) − 0.5))
```

- 起きやすさ＝今月の事後平均（Beta(1,1)、分母は本文のある日誌）
- 準備度：0 手がない／1 担当は決まっている／2 手順が書いてある／3 試して効いた（3なら0になる）
- 重み w は慣習で、正解はない。**機械が出すのは提案順まで。順番を決めるのは人**（入れ替えた理由を残す）

## データと保存先

| データ | 足した日誌・判定・決定 |
|---|---|
| 架空サンプル（50件） | ブラウザのセッション内だけ（CSV/Markdownで保存可） |
| **手元の日誌ファイル** `data/raw/diary.csv` | `data/raw/` に保存（`.gitignore` 済み）。毎日使うのはこちら |
| CSV/TSV をアップロード（一時） | セッション内だけ |

手元ファイルのときの中身：

```
data/raw/diary.csv                日誌の原本（毎日1行ずつ足す）
data/raw/routine/tag_checks.csv   毎日：タグへの OK／直し
data/raw/routine/labels.csv       毎週：困りごとかどうかの判定（④でも同じものを編集）
data/raw/routine/monthly.csv      毎月：準備度・人が決めた順番・打つ手・担当・期限
data/raw/photos/                  写真（位置情報などの EXIF を消して保存）
```

## ページ構成

| 区分 | ページ | URL |
|---|---|---|
| ルーティン | 今日のルーティン／毎日／毎週／毎月 | `/`・`/nisshi`・`/shukei`・`/tsuki` |
| 学ぶ（第1〜3回） | 0 データと匿名化／① 1件を読む／② for・ifで数える／③ pandasで表にする | `/data`・`/kai1`・`/kai2`・`/kai3` |

## ファイル

| ファイル | 役割 |
|---|---|
| `app.py` | 設定・データ準備・ページ構成（`st.navigation`） |
| `routine_core.py` | 日→週→月の計算部品（タグ案、週・月の区切り、候補、月の推定、優先度、ふりかえり） |
| `diary_core.py` | 第1〜3回と発展の計算部品（匿名化・KWIC・for/if・pandas・ベイズ推定・ナイーブベイズ） |
| `store.py` | 保存先（手元ファイル／セッション）、写真の EXIF 除去 |

| `tests/` | `test_core.py`（第1〜3回）・`test_routine.py`（ルーティン） |

## この版での変更

- 毎日／毎週／毎月の時系列を軸に、ページを再編（旧タブ 0〜⑥ は「学ぶ」「深掘り」に残存）。
- 匿名化の符号を「辞書の氏名 → 記入者」の順に振るよう変更。日誌を後ろに足しても既存の判定キーがずれない（テストあり）。
- 写真の EXIF（撮影位置など）を消して保存。アップロード上限を 15MB に。
- `.claude/settings.json` で `Read(./data/raw/**)` を deny（人の注意ではなく設定で防ぐ）。

## 安全の約束

- 実データは**手元で** `streamlit run` する。Streamlit Community Cloud 等の公開サーバーには架空サンプルだけを置く。
- 生データ・写真・記録は `data/raw/`（`.gitignore` 済み）。置換の対応表は共有しない。
- 担当は名前ではなく役割か作業者記号で書く。送信・発注・シフト確定は人が行う。
- 写真に人の顔・車のナンバー・伝票が写っていないかを、保存前に確認する。
