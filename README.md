# 作業日誌 困りごと分析ダッシュボード（Streamlit・積み上げ版）

テキスト分析 第1回〜第3回の道具を**1段ずつ積み上げて**、同じ作業日誌を分析するダッシュボード。
旧版 `作業日誌 困りごと分析_インサイト.html` の機能（匿名化・KWIC・人の判定・ベイズ推定・判定モデル）を引き継ぐ。

## 起動

```bash
pip install -r requirements.txt
streamlit run app.py
pytest -q          # 計算部品の検証（期待値は人が先に決めたもの）
```

## タブ構成（積み上げ）

| タブ | 回 | 使う道具 | 確かめること |
|---|---|---|---|
| 0 データと匿名化 | 前提 | 辞書＋自動置換、置換ログ | 対応表は共有しない |
| ① 1件を読む | 第1回 | `len` / `count` / `in`、KWIC、NFKC、文字バイグラム | 文字数・回数は意味ではない |
| ② for・ifで数える | 第2回 | `for`・`if`、DNCL、トレース表（スライダーで1件ずつ）、確認問題 | 件数≠回数、欠損は数えない |
| ③ pandasで表にする | 第3回 | `isna`、マスク、`str.contains(regex=False, na=False)`、`&`、`groupby`、分母、`count`/`sum`、`to_csv` | 欠損＝0ではない、分母を明示 |
| ④ 原文を読む・判定 | 発展 | KWIC＋人の判定（表で編集・CSV保存/読込）、ずれ表、共起語 | 機械は「一致」まで |
| ⑤ インサイト | 発展 | Beta(1,1) ベイズ推定、タイムライン、連鎖（ラグ）、復旧日数、エージェント示唆 | 前後関係は因果ではない |
| ⑥ 判定モデル | 発展 | ナイーブベイズ（文字2-gram）、1件抜き交差検証、多数派ベースライン | 予測は順番づけ、最終判断は人 |

## 旧HTML版からの主な変更

- 第3回に合わせ、**本文欠損2件・作業時間欠損5件**をサンプルに追加（`data/sample_diary.csv`）。割合の分母は「本文あり」を既定にし、全レコード分母と切替可能。
- 型を `string` / `Float64` に指定、`df_raw` を残して入力が変わっていないかを `df.equals` で確認。
- 第1回・第2回の内容（`len/count/in`、for・if、DNCL・トレース表、確認問題）をタブ①②として残存。
- 判定モデルに**多数派ベースライン**を併記（正答率の見かけの高さを防ぐ）。
- 計算部品を `diary_core.py` に分離し、`tests/` で期待値検証。

## 安全の約束

- 実データは**手元で** `streamlit run` する。Streamlit Community Cloud 等の公開サーバーには架空サンプルだけを置く。
- 生データは `data/raw/`（`.gitignore` 推奨）、対応表（置換の記録）は共有しない。
- Claude Code を使う場合は `.claude/settings.json` で `Read(./data/raw/**)` を deny にする。
